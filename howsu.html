Howsu

가족 공동 반려동물 케어 앱

2025.11 – 12 · 3인 팀 프로젝트팀장 · Android 개발
Kotlin Jetpack Compose Firebase Auth Firestore Cloud Functions FCM

가족 구성원이 반려동물의 담당자별 Todo·반복 일정·알림을 공유하는 Android 앱입니다.

반려동물 돌봄 과정에서 가족 구성원 간 역할을 분담하고, 공동 일정과 할 일을 관리하며 반려동물의 일상을 공유할 수 있도록 구성했습니다.

자료 링크
프로젝트 상세 README 및 구현 코드
팀 저장소 GitHub Repository

주요 기능 화면

이미지를 클릭하면 원본 비율로 확대할 수 있습니다.

로그인 화면은 개발 당시 캡처입니다. 최종 배포에서는 Google 및 이메일 로그인을 제공했습니다.

담당 역할

인증, 가족 연결, Todo·일정 관리, 푸시 및 로컬 알림, Navigation 설계, 팀원들이 개발한 기능 간 데이터 연동 및 통합

주요 서비스 기능

  • 가족 공간: QR 코드·고유 ID를 활용한 가족 연결 및 반려동물 정보 공유
  • 돌봄 Todo: 반려동물·담당자별 할 일 등록, 완료 체크, 미완료 항목 자동 이월
  • 공유 일정 및 알림: 반복 일정과 미리 알림, 새 할 일 등록 시 담당자 푸시 알림
  • 가족 피드: 사진·동영상 및 댓글을 통한 반려동물의 일상 공유

주요 구현 흐름

  1. 담당자를 지정해 Todo 등록
  2. Firestore 문서 생성
  3. Cloud Functions 이벤트 감지
  4. 담당자 FCM 토큰으로 푸시

핵심 구현 및 문제 해결

핵심 과제 구현 및 설계 과정
01. 외부 OAuth 인증 연동 Kakao/Naver OAuth Cloud Functions Firebase Auth
외부 OAuth 토큰을 Firebase Auth에 바로 사용할 수 없어 별도의 인증 연동 구조를 구성했습니다. 앱에서 OAuth 토큰 획득 → Cloud Functions에서 유효성 검증 → Firebase Custom Token 발급 → 앱 로그인 순으로 인증 흐름을 구현했습니다.

※ Kakao/Naver 로그인은 플랫폼 심사 미승인으로 최종 배포에서 제외했으며, Google 및 이메일 로그인을 제공했습니다.
02. 가족 그룹 연결 및 데이터 정합성 Firestore Batch Write ZXing
QR 코드와 고유 ID를 활용해 가족 그룹에 참여할 수 있도록 구현했습니다. 가입·탈퇴 과정에서 사용자 문서와 가족 그룹 문서 등 여러 Firestore 문서가 일부만 변경되지 않도록 관련 쓰기 작업을 Batch Write로 묶어 원자적으로 처리했습니다. Firebase Auth 계정 삭제는 Firestore Batch의 원자성 범위 밖이라는 점도 구분했습니다.
03. Todo 및 반복 일정 관리 Kotlin Firestore Batch Delete
반려동물별·담당자별 할 일을 등록하고 완료 상태를 관리하며, 미완료 항목을 다음 날로 자동 이월하도록 구현했습니다. 반복 일정 삭제에서는 '이번 일정만'과 '이후 일정 전체'를 분기하고, 반복 규칙과 날짜 조건으로 삭제 대상을 결정한 뒤 Batch Delete로 일괄 처리했습니다.
04. 이벤트 기반 담당자 푸시 알림 Cloud Functions Firestore FCM
새로운 Todo가 등록되면 해당 담당자에게 알림이 전달되도록 Todo 생성 → Firestore 이벤트 기반 Cloud Functions 실행 → 담당자 FCM 토큰으로 전송하는 흐름을 구성했습니다. 데이터 생성 이벤트와 서버 측 알림 처리를 연결했습니다.
05. 로컬 일정 알림 및 사용자 설정 AlarmManager DataStore
일정 미리 알림은 AlarmManager를 활용하여 로컬에서 예약했습니다. 알림 수신 시 DataStore에 저장된 사용자 알림 설정을 확인하도록 구현했습니다.
06. 서버 오류 추적 및 재배포 Cloud Functions Functions Log FCM
Cloud Functions 배포 후 Todo가 정상적으로 생성되었음에도 담당자에게 FCM 알림이 전달되지 않는 문제가 발생했습니다. 서버 로그를 추적하여 Firestore 인스턴스 선언 누락을 확인하고, 관련 코드를 수정한 뒤 재배포하여 해결했습니다.
07. 화면 상태 관리 및 데이터 갱신 ViewModel SavedStateHandle Navigation
일정 수정·삭제 후 이전 화면으로 돌아왔을 때 기존 목록이 그대로 유지되는 문제가 발생했습니다. SavedStateHandle을 활용하여 화면 간 새로고침 신호를 전달하고 변경된 데이터가 반영되도록 화면 갱신 흐름을 수정했습니다.

추가 구현 세부 사항
Functions 로그에서 admin.firestore() 인스턴스 선언 누락을 확인했습니다. 이벤트 알림(FCM)과 예약 알림(AlarmManager)의 역할을 분리했습니다.

핵심 경험

여러 사용자가 동일한 데이터를 변경하는 환경에서 문서 간 데이터 정합성과 원자적 변경을 고려했습니다. 외부 인증 서비스와 Firebase를 연동하고, 데이터 생성 이벤트부터 서버 실행 및 알림 수신까지 이어지는 전체 흐름을 구현했습니다. 서버 로그를 활용하여 기능 간 연결 과정에서 발생하는 장애 지점을 추적하고 해결했습니다.
