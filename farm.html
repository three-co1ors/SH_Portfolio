PROJECT 03

왓더팜

2D 모바일 농장 게임

5인 팀 프로젝트 · 대상 / MVP게임 시스템 · 데이터 관리
Unity C# Firebase Realtime Database Git

작물 재배·진화, 아이템 수집, 상점 및 퀘스트 시스템을 결합한 2D 모바일 농장 게임입니다.

기본 농장 시스템에 작물 진화, 도감 수집, 아이템 거래 및 퀘스트를 연결하여 게임 진행에 따른 성장과 수집 요소를 제공했습니다.

자료 링크
프로젝트 상세 README 및 구현 코드

주요 기능 화면

이미지를 클릭하면 원본 비율로 확대할 수 있습니다.

담당 역할

인벤토리, 도감, 연구소, 상점, 공통 UI, Firebase 기반 데이터 저장·복원 및 팀원 간 기능 통합

주요 게임 기능

  • 농장 운영: 작물 재배·수확 및 아이템 획득
  • 성장 및 수집: 연구소를 통한 작물 진화, 인벤토리·도감을 활용한 수집 현황 확인
  • 상점 및 퀘스트: 아이템 구매·판매, 메인·서브·일일 퀘스트 진행
  • 진행 저장: 게임 진행 데이터 저장 및 재실행 시 복원

주요 구현 흐름

  1. 게임 시작 → Firebase 데이터 로드
  2. 로드 완료 플래그 확인
  3. 게임 진행 데이터 복원
  4. 변경 사항 안전하게 저장

핵심 구현 및 문제 해결

핵심 과제 구현 및 설계 과정
01. 아이템 및 재화 관리 시스템 C# Singleton
Singleton 기반 InventoryManager를 구성하여 아이템 추가·삭제·보유 수량을 관리했습니다. 작물 수확 및 진화 결과를 도감에 연결하고, 연구소와 상점에서 동일한 아이템·재화 관리 로직을 활용하도록 기능을 연동했습니다. 여러 게임 시스템에서 공통으로 사용되는 데이터를 일관된 방식으로 관리하도록 구성했습니다.
02. 공통 UI 및 팝업 제어 Unity UIManager
각 기능에서 팝업을 개별적으로 제어하면서 UI 간 충돌이 발생했습니다. 기존 팝업을 닫고 선택한 창만 열도록 공통 UIManager를 구성했습니다. 팀원들이 동일한 API를 사용하여 팝업을 제어할 수 있도록 사용 가이드도 작성했습니다.
03. 비동기 데이터 저장 및 복원 Firebase Realtime Database C#
퀘스트 진행 데이터를 비동기로 저장하고 게임 재실행 시 기존 진행 상태를 복원하도록 구현했습니다. 비동기 데이터 로드가 끝나기 전에 저장이 실행되어 기존 퀘스트 데이터가 초기값으로 덮이는 문제가 발생했습니다. isLoaded Guard를 적용하여 데이터 로드가 완료되기 전에는 저장이 실행되지 않도록 수정했습니다.
04. 퀘스트 식별자 충돌 해결 Firebase Realtime Database C#
메인 퀘스트와 일일 퀘스트에서 동일한 DB Key를 사용하면서 식별자가 충돌하는 문제가 발생했습니다. 퀘스트 유형별 식별자 네임스페이스를 분리하여 서로 다른 유형의 데이터가 충돌하지 않도록 해결했습니다.

추가 구현 세부 사항
SaveToDB() 실행 전 if (!isLoaded) return;으로 미완료 시 저장을 차단했습니다.

핵심 경험

여러 게임 기능에서 공통으로 사용하는 아이템·재화 관리 및 UI 제어 로직을 통합했습니다. 특히 비동기 데이터의 로드·저장 순서와 데이터 식별자 설계가 데이터 안정성에 미치는 영향을 경험했습니다. 공통 API와 사용 가이드를 구성하여 팀원 간 기능 통합 과정에서 발생하는 문제에도 대응했습니다.
